# clangd LSP health check

`clangd --check=<file>` replays exactly what the editor's LSP session would do
(load compilation database, parse the file, build the AST, run diagnostics) and
prints the result to the terminal. If this passes, Neovim's clangd will work;
if it fails, the error output pinpoints why.

## Steps

1. Find the compilation database in the project root, in this order:
   - `compile_commands.json` (preferred; usually generated by `bear -- make`
     or `cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`)
   - `compile_flags.txt` (fallback; one flag per line)
   If neither exists, tell the user and offer to generate one: prefer a
   `make compdb` target if the Makefile has one (clang `-MJ` based), else
   `bear -- make` — but note bear 4.x is broken with nix's script-wrapper
   clang on macOS (EAGAIN / os error 35).
2. Check staleness: if any `Makefile`/`CMakeLists.txt` is newer than
   `compile_commands.json`, warn that the database may be stale and offer to
   regenerate it.
3. Run the check on each source file the user cares about (default: all of
   `src/*.c`), inside the project dev shell if there is one:

   ```sh
   clangd --check=src/main.c
   # in a Nix flake project:
   nix develop -c clangd --check=src/main.c
   ```

4. Interpret the output:
   - `All checks completed, 0 errors` — LSP is healthy for that file.
   - `Failed to find compilation database` — DB missing or in the wrong
     directory (clangd searches from the file's directory upward).
   - `error: ... file not found` on an `#include` — include path missing from
     the database; regenerate with bear, or check `-I` flags.
   - Diagnostics listed under "diagnostics" are what Neovim would show inline;
     real code errors, not LSP misconfiguration.
5. Report a per-file pass/fail summary. If a `.cache/clangd` directory exists
   and results look stale even after regenerating, suggest deleting it
   (clangd's index cache).

## Notes

- clangd version should roughly match the compiler; in Nix dev shells both come
  from the same `clang-tools`/`clang` packages, so this is normally fine.
- This checks the *server* side only. If clangd passes here but Neovim still
  misbehaves, the problem is editor-side: `:LspInfo` / `:checkhealth lsp` in
  Neovim, root-dir detection (needs `.git` or the compilation DB), or multiple
  clangd binaries on PATH (`:echo exepath('clangd')` vs `which clangd`).
